What is learning here?

A renderer turns splats into pixels

Each splat has a 2D center, two positive scales, a rotation, an opacity and an RGB color. At a pixel, its unnormalized Gaussian footprint multiplies its opacity. The renderer then blends the splats in a fixed front-to-back order, including the remaining background. Overlap and occlusion affect which parameters receive useful gradients.

The target defines a loss

L1 is the mean absolute error over every pixel and RGB channel. SSIM compares local means, variances and covariance. The combined objective is (1 − λ)L1 + λ(1 − SSIM). The paper uses λ = 0.2. The colored residual plot shows the per-pixel mean absolute RGB error, not the SSIM contribution. Its scale stays fixed, so a darker image means less error.

Gradients change the parameters

The model differentiates the image loss through alpha compositing and the Gaussian footprint. Adam updates the allowed parameter groups. Shape includes both scales and rotation. Positive scales use an exponential parameterization. Opacity and RGB use sigmoid parameters in this teaching model. The target image stays fixed, and no reference splat parameters enter the optimizer.

A good image fit can have several explanations

Different overlapping splats can produce similar pixels. Color and opacity can compensate for one another, and a frozen parameter group can force other groups to absorb the error. This lab uses a fixed number of 2D splats. Original 3DGS additionally projects 3D covariances, handles view-dependent colors and changes model capacity through cloning, splitting and pruning.

Try this sequence

Run 50 steps and inspect the residual. Freeze Position, reset the splats, and repeat. Then enable Position and continue. Change λ to see the exact loss arithmetic update. The history restarts when the objective changes, so values from different objectives are not joined as one curve.

Demo-specific numerical settings. Adam uses smaller rates for position and shape, with all rates multiplied by 1 / (1 + t / 180) at iteration t. Stability bounds keep centers in [−0.15, 1.15], scales in [0.02, 0.5], and opacity/color logits in [−8, 8]. These are teaching-model settings, separate from the original 3DGS schedule.

Why an extra view changes the answer

One center is shared by every camera

This lab renders one isotropic Gaussian with fixed size, color and opacity. Only its 3D center (x, y, z) learns. Calibrated orthographic camera 1 sees (x, y), camera 2 sees (z, y), and a held-out camera sees a 45° mixture of x and z. The images have the same pixel loss as the fitting lab, with λ = 0.2.

Camera 1 cannot measure z

Moving this Gaussian along z leaves the first rendered image unchanged. The image-loss derivative with respect to z is therefore zero. Training can match the first target while preserving an incorrect initial depth. The gray vertical line marks centers with the same camera-1 horizontal projection as the reference.

The second view constrains the missing direction

Camera 2 sees the z displacement as a horizontal image error. When both cameras train the same center, their constraints intersect. The optimizer receives image gradients in the previously invisible direction. The held-out camera provides an additional image check and never contributes to training.

This is a controlled identifiability example

The cameras and appearance are known, the scene has one splat, and the targets are noise-free. Real 3DGS has more unknowns, occlusions, calibration error and potentially unobserved surfaces. Multiple views provide stronger constraints, but low training loss alone does not prove that the inferred scene is the unique physical geometry.

Try this sequence

Keep Camera 1 only and run 50 steps. Compare the small training loss with the held-out error and the wrong z coordinate. Select Cameras 1 + 2 and run another 50 steps without resetting. Watch the shared center move toward the intersection of the two image constraints.

Demo-specific numerical settings. Adam uses rate 0.035 / (1 + t / 100), with center coordinates bounded to [−0.1, 1.1]. In the one-camera case, z and its optimizer momentum remain fixed because z has no effect on that image. Switching cameras preserves the estimated center.
