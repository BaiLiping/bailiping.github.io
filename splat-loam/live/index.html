How to explore

Rendering: every angular cell specifies an emitted beam direction. Click a cell to see that exact ray, its intersections with several splats, and the weighted range. “Spherical” refers to azimuth and elevation coordinates; the rectangular image is an unwrapped angular window (110° × 48°). Its values are distances, not camera RGB. Grayscale and optional false color only display those values.

How many rays touch one splat? the count shown for A tests the sampled rays against its chosen 3σ ellipse (u² + v² ≤ 9 in normalised local coordinates). The Gaussian itself has unbounded support, so this is a teaching footprint, not a renderer cutoff or a count of returned points. The count depends on scale, orientation, sensor pose, and angular sampling. Opacity changes contribution weights, not this geometric count.

Registration: run the room-corner case, then switch to a corridor. The geometric residual can become very small while motion along the corridor remains unobservable. Increase the synthetic noise along surface normals to see an actual residual floor.

Scope: this is an explanatory simulation. It uses three planar 3D Gaussians and per-ray sorting, not the paper's GPU tile rasteriser. Its registration lab implements only the geometric point-to-line SE(2) analogue. Splat-LOAM uses SE(3), rendered-keyframe geometry, and a joint geometric plus range-image warping objective; Gaussian map optimisation is a separate operation. The repository's optional median-depth mixture is omitted.
