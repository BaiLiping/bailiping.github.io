# 911 engine comparison

This page is the **Engine lab** tab of the 911 GT3 page, which loads it in a frame
(`/porsche-911-gt3/#engine-lab`). Opened on its own, it forwards to that tab, so visitors always see it below the
GT3 header. It carries `noindex, indexifembedded`, which keeps it out of the sitemap but lets search engines index
it as part of the GT3 page.

The main page compares the European 1978 Porsche 911 Turbo 3.3 (930/60) with the naturally aspirated
911 SC 3.0 (930/03). The two models use the same scale, crank-axis reference frame and camera angle.
On load both engines start exploded, hold for one second, then assemble together. Parts closest to their
seats return first. An interaction takes over immediately. With reduced motion the models start assembled.
Drag or zoom either view to move both. On narrow portrait screens the engines appear one above the other.

Choose **Gas flow** to see the intake, exhaust and fan cooling streams on both complete engines.
The Turbo also shows compressor discharge, cooled charge air and exhaust through the wastegate.
Choose **Intake** or **Exhaust** to isolate one system. **Cutaway** exposes
the opposed cylinders and **Exploded** spreads the parts. **Run engines** moves both mechanisms at the
same demonstration speed. Select a part to see its name and its counterpart when present. In the assembled
and cutaway views, double-click a part or use **Move selected part** to pull it out. Reset restores the starting view.

Unofficial. Built from published dimensions and photographs studied as reference; not affiliated with Porsche.

## Files

| File | What |
|---|---|
| `index.html`, `entry.js` | page markup, captions and viewer startup |
| `compare.js`, `comparison.css` | linked comparison renderer, controls and layout |
| `assembly.js` | shared opening timing and per-part assembly motion |
| `engineSC.glb`, `engineSC.json` | 911 SC geometry, animation and gas paths, generated by the SC build |
| `flow.js` | gas-flow particles along the paths exported with the model |
| `engine930.glb`, `engine930.json` | the model and its viewer data, generated by `model/build.py` |
| `stamp.py` | stamps every asset address with a version taken from the assets' contents |
| `model/` | the Blender build script, its dimensions (`PARTS.md`) and its limits (`NOTES.md`) |
| `vendor/` | Three.js r187, only the parts used, bundled into one self-hosted file (MIT, licence beside it) |

## Rebuild

```
# the model (Blender 5.2 on PATH)
blender -b --factory-startup --python engine-lab/model/build.py
blender -b --factory-startup --python engine-lab/model/build.py -- --sc

# the Three.js bundle, only when vendor/three-entry.js changes
mkdir /tmp/three && cd /tmp/three && npm init -y && npm install three@0.187.0 esbuild
cp <repo>/engine-lab/vendor/three-entry.js . && npx esbuild three-entry.js --bundle --minify --format=esm \
  --target=es2020 --legal-comments=none --outfile=<repo>/engine-lab/vendor/three.bundle.min.js
```

## Check

```
python3 -m http.server 8765        # from the repository root, then open http://localhost:8765/porsche-911-gt3/#engine-lab
python3 scripts/build-search-index.py --check
python3 engine-lab/stamp.py --check
```

After changing any script, the stylesheet or the model, run `python3 engine-lab/stamp.py`. It rewrites the `?v=`
stamp on every asset address from the assets' contents, so a browser that has an older copy cached fetches the
new files together instead of running old code against a new page.

The interactive views load their assets from this site and use WebGL 2. The comparison shows still renders of both engines during loading and when 3D is unavailable.
